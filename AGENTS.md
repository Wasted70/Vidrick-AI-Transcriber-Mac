# Mac-only development boundaries

- This folder is the isolated Apple Silicon Mac prototype, not the Windows app.
- Windows visual references may be read, but recreating their appearance here does not authorize Windows edits. Only change the Windows project when the user explicitly requests a Windows update/fix.
- The Windows project at `C:\Vidrick_AI_Transcriber_4.3 - Main` is read-only reference. Windows remains the primary product and receives customer-feedback fixes first.
- Do not edit, build, test, install packages into, publish from, or create caches in the Windows project. Never import its modules or add it to `sys.path`.
- Keep all code, tests, outputs, environments, and build work inside this Mac folder. No links to shared writable source or automatic two-way synchronization.
- Do not copy whole project trees, customer recordings, account state, secrets, signing keys, installers, CUDA libraries, portal code, or website code here.
- Current scope includes preflight, the local Editor, one-recording transcription, and user-triggered in-app engine/model setup on native arm64 macOS. The user authorized reading the selected recording on Start, downloading pinned tools/sources/models on Set Up, compiling local tools, opening Apple's developer-tools installer on its dedicated button, and remembering setup paths. Never download, install, build, or contact the network at startup or from the Windows UI preview. No licensing requests, account activation, automatic updates, telemetry, or production services.
- This independent development integration is not a packaged/licensed Vidrick product. A distributable functional port must preserve licensing enforcement; do not port or bypass production licensing or imply that the development pipeline is release-ready.
- Native M-series/arm64 macOS is the initial target. Intel/Rosetta and Apple GPU acceleration are outside the current scope.
- The user authorized a separate `--windows-preview` UI development mode in this Mac folder. It must be explicitly selected, Windows-only, visibly labeled, non-transcribing, and disconnected from the production Windows app. Preserve the native-Mac guards on `--check` and `--preview`.
- Do not claim Mac compatibility, benchmark results, or release readiness from Windows-based or mocked tests. Native Mac testing is still required.
- Do not push, publish, purchase services, or configure hosted builds without a user request covering that work.
- Run tests with `python -B -m unittest discover -s tests -v`. Do not install dependencies globally.
- File-I/O tests must use synthetic files under this project's ignored `test-output/`, never customer recordings. For Editor changes, also run the opt-in real Tk tests with `VIDRICK_TEST_TK=1` in a desktop session. Native Mac behavior remains unverified until actually checked on a Mac.
- Pipeline intermediates and diagnostics belong only in ignored `runtime-output/`, in a private per-job directory cleaned after success, cancellation, or failure. Keep tools/models in ignored `local-tools/` and `models/` if storing them here. Tests may inject synthetic backends/subprocesses on Windows, but must not enable real transcription in the Windows preview. Workers must never call Tk; cancellation and close must wait asynchronously for worker cleanup.
- Managed setup belongs only in ignored `local-setup/`: verified download cache, versioned tools, models, temporary builds, and atomic selection preferences. Use pinned HTTPS artifacts with exact sizes and SHA-256, validate extraction paths, and preserve the previous selection on cancellation/failure. No Homebrew, pip, sudo, system-wide installs, quarantine removal, or security-setting changes. Apple's own developer-tools installer is the explicit user-controlled exception to project-local installation. Native build/inference validation remains required.
- History and autosave recovery are authorized local features. Keep their database and lock in ignored `local-history/mac/`, or isolated `local-history/windows-preview/` for the explicit Windows UI preview. Save completed transcript text and minimal metadata, never recordings. Autosave Editor drafts separately from the user's files and completed results; recovery opens an editable copy. Rename/delete affect only the selected local library entry. Native startup may read this library and offer recovery; no startup network or engine activity. Tests inject in-memory stores or synthetic stores under `test-output/`; never use real library data. Preserve pending results and drafts after failed storage operations, and do not silently prune history.

- Subtitle exports are authorized: write SRT/VTT only to the user-selected destination, using current text and real segment offsets. Keep offsets with local History/recovery, never infer missing timings, and preserve Editor dirty state after export. Schema upgrades must preserve existing library data. Synthetic export tests belong under ignored test-output/.
